## 🔍 WCAG 2.2 AA Core Principles Verification

### 1. Principle 1: Perceivable

- **1.1.1 Non-text Content**:
  - All Lucide SVG icons are accompanied by `aria-hidden="true"` so screen readers ignore visual decorations.
  - Inspiration image upload enforces a non-empty `alt-text` input field (`#alt-text-input`) before enabling visual BOM extraction.
  - Progress bars and status badges display both textual labels and ARIA values.
- **1.3.1 Info and Relationships**:
  - Real semantic HTML elements are used throughout:
    - Comparison Matrix is a true accessible HTML `<table>` with `<caption className="sr-only">`, `<th scope="col">` column headers, and `<th scope="row">` category headers.
    - Semantic landmarks: `<header role="banner">`, `<main id="main-content">`, `<section aria-label="...">`, `<footer role="contentinfo">`.
    - Form inputs have associated `<label>` elements or descriptive `aria-label` / `aria-labelledby` attributes.
- **1.4.3 Contrast (Minimum)**:
  - Text contrast exceeds 4.5:1 on light (`#0f172a` on `#ffffff`) and dark (`#f8fafc` on `#0f172a`) backgrounds.
  - Large headings and interactive component borders exceed 3:1 contrast.
- **1.4.10 Reflow (320px & 400% Zoom)**:
  - Responsive Tailwind layout adjusts from multi-column grids to single-column flex layouts at 320px without horizontal scroll or content clipping.
- **1.4.11 Non-text Contrast**:
  - Interactive badges, sliders, toggle switches, and buttons meet the 3:1 boundary contrast ratio.

## ⌨️ Principle 2: Operable

- **2.1.1 Keyboard Navigation**:
  - Every interactive element (buttons, tabs, inputs, modal dialogs, preset triggers) is 100% operable via keyboard (`Tab`, `Shift+Tab`, `Space`, `Enter`).
- **2.1.2 No Keyboard Trap**:
  - `<AccessibleModal>` traps focus within the active dialog while open, and releases focus cleanly upon closing.
  - Pressing `Escape` closes any open dialog immediately.
  - Active element focus is remembered and restored to the triggering button upon dismissal.
- **2.4.1 Bypass Blocks (Skip Link)**:
  - A high-visibility skip-link (`<a href="#main-content" className="skip-link">Skip to main content</a>`) is the first focusable element on every page.
- **2.4.7 Focus Visible**:
  - Global CSS rules enforce high-contrast focus rings (`focus-visible:ring-2 focus-visible:ring-brand-500 focus-visible:ring-offset-2`).
  - Outline is never suppressed without an accessible replacement ring.
- **2.5.5 / 2.5.8 Target Size**:
  - All interactive buttons, icon triggers, and sliders have hit targets of at least 24×24 CSS pixels (most are 36×36 px or larger).

---

## 🧠 Principle 3: Understandable

- **3.1.1 Language of Page**:
  - `apps/web/index.html` explicitly declares `<html lang="en">`.
- **3.2.1 On Focus / 3.2.2 On Input**:
  - Focusing or typing into an element never causes an unexpected context change or automatic form submission.
- **3.3.1 Error Identification / 3.3.2 Labels or Instructions**:
  - All input errors (upload file type rejections, budget overruns, speech mic permission denied) are rendered with `role="alert"` and clear, actionable instructions.
- **3.3.4 Error Prevention (Financial & Schedule Reversals)**:
  - Destructive or cascading actions (e.g., booking a quote that causes a budget overrun, applying a day-of schedule ripple fix) require explicit human confirmation via accessible modal dialogs.
  - The system never auto-commits budget cuts or schedule shifts without showing exact before-and-after deltas.

---

## 🛠️ Principle 4: Robust

- **4.1.2 Name, Role, Value**:
  - Native range slider (`<input type="range">`) uses:
    - `aria-valuemin={0}`
    - `aria-valuemax={100}`
    - `aria-valuenow={sliderValue}`
    - `aria-valuetext="Splurge tier. High-impact luxury upgrades enabled."` (word-based announcement instead of raw numeric value).
  - Screen reader live announcements are routed through `<LiveAnnouncer>` with `aria-live="polite"` and `aria-atomic="true"`, with 300 ms debouncing to avoid voice synthesizer clutter.
- **4.1.3 Status Messages**:
  - SSE connection status, budget updates, and voice recognition state provide immediate `aria-live` or `role="status"` feedback.

---

## 🎤 Multimodal & Assistive Equivalency

- **Voice Input Fallback**:
  - Web Speech API microphone input in the Execute view is accompanied by a persistent, fully interactive multi-line text `<textarea>`.
  - If microphone access is denied or unsupported, the user receives an informative message and can type disruptions effortlessly.
- **Motion Reduction**:
  - CSS animations (`@keyframes pulse`, `@keyframes fadeIn`) respect the `@media (prefers-reduced-motion: reduce)` media query.
- **Color Independence**:
  - Hidden cost risk flags and budget overruns use explicit textual labels (_"CRITICAL"_, _"WARNING"_, _"Overrun detected"_) and distinct icon shapes (`AlertTriangle`, `AlertCircle`, `CheckCircle2`) in addition to color.
